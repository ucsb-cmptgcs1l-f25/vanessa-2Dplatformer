# SproutCast
App Type: 2D Platformer Tech Stack: Unity (C#), using the Unity 2D Engine, Jetbrains Rider, Rigidbody2D physics, and custom scripts for resource collection and bridge-building mechanics

# Tech Stack
Unity, in combination with Jetbrains Rider, is what I'm currently using to craft my 2D platform adventure game. It allows me to easily add sprites and images into my game, and attach different properties to them. For example, I can change the physics material of the object to have 0 friction to create a "slippery" visual.

# Project Plan
Sproutcast is set in various biomes where our Sprout must strategically build to reach the other side. The Sprout must retrieve different resources from the environment, only able to carry one thing at a time. Each resource in the environment has different pros and cons. For instance, the Sprout starts in the forest biome. Each biome has three levels, which rise in difficulty. On the levels, the Sprout must reach the other side of the bridge to complete the level. In this example, our Sprout can pick up twigs, which are light but break easily in the bridge. Otherwise, they can grab a wooden log, which is heavy (slows down Sprout) but is sturdier in the bridge. The player uses their creativity to figure out the best way to reach the other side. After completing the level and moving on to the next, the player may have more time pressure or have a more difficult biome, such as more wind or progress into the snow biome. Unlike a typical 2D platformer game, SproutCast enables users to strategically think and problem solve to craft the best combination of resoources to reach the other side. 

# User Roles
The main user for my game is the game player. They are able to navigate through the game using AD keys or the left and right arrows. The spacebar is for jumping. Eventually, clicking E will allow the user to grab resources from the environment. Their role is to get Sprout to complete all platform levels and reach the end! They need to strategically build each bridge in order to make it to the next biome.

# Roles and Permissions
My game may eventually attempt to implement a log in system, since each player will want their progress saved each time they log out. It doesn't need to be restricted since they can not interact with any other person or player during the game.
